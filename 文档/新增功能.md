# GTFS 公交数据分析系统 - 新增功能建议

> 基于当前已实现功能（线路/站点浏览、准点率分析、换乘规划、线路对比、实时监控、收藏夹、用户管理、管理看板）和现有数据，提出以下三类新增功能建议。

---

## 一、不依赖现有数据的辅助性功能

以下功能不需要 GTFS 数据或准点率数据，属于系统层面的辅助增强。

### 1. 多语言国际化（i18n）

**功能描述**：系统支持中文/英文切换，方便不同语言背景的用户使用。

**实现思路**：
- 前端引入 `vue-i18n`，抽取所有界面文本为语言包
- 顶部导航栏添加语言切换按钮
- 后端 API 错误信息支持多语言返回

**工作量**：中等（主要是文本抽取工作）

---

### 2. 深色模式（Dark Mode）

**功能描述**：支持浅色/深色主题切换，提升夜间使用体验。

**实现思路**：
- Element Plus 已内置深色模式支持，配置 CSS 变量即可
- 地图组件切换深色底图（Leaflet 支持 CartoDB Dark Matter 等深色瓦片）
- 用户偏好持久化到 localStorage

**工作量**：较小

---

### 3. 数据导出中心

**功能描述**：在各页面（线路列表、站点列表、准点率统计、时刻表等）提供 CSV / Excel / PDF 导出功能。

**实现思路**：
- 前端使用 `xlsx` 库导出 Excel，`jsPDF` 导出 PDF
- 统一封装导出组件，各页面复用
- 支持导出当前筛选条件下的数据

**工作量**：中等

---

### 4. 操作日志与审计

**功能描述**：记录管理员的关键操作（用户管理、配置修改、数据刷新等），便于审计追溯。

**实现思路**：
- 新增 `audit_logs` 表（user_id, action, target, detail, created_at）
- 后端在关键接口添加日志记录中间件
- 管理看板新增"操作日志"页面，支持按时间/用户/操作类型筛选

**工作量**：较小

---

### 5. 系统通知与消息中心

**功能描述**：用户可订阅关注的线路，当准点率低于阈值时收到站内通知；管理员可发布系统公告。

**实现思路**：
- 新增 `user_subscriptions`（user_id, route_id, region, threshold）和 `notifications`（user_id, type, title, content, is_read）表
- 后端定时检查准点率，触发通知写入
- 前端顶部导航栏显示未读通知角标，点击展开通知列表

**工作量**：中等

---

### 6. 仪表盘自定义（Dashboard Widgets）

**功能描述**：用户可自定义首页仪表盘，拖拽排列关注的数据卡片（如特定线路准点率、收藏站点时刻表、实时车辆数等）。

**实现思路**：
- 前端使用 `vue-grid-layout` 实现拖拽布局
- 用户配置持久化到数据库（`user_dashboard_config` 表）
- 预设若干 Widget 类型：准点率卡片、时刻表卡片、地图卡片、统计图卡片

**工作量**：较大

---

## 二、使用现有数据可新增的功能

以下功能完全基于已有的 GTFS 静态数据和准点率数据实现。

### 1. 站点服务频率热力图

**功能描述**：在地图上以热力图形式展示各站点的班次密度（每日经过班次数），识别高频枢纽站和低频末端站。

**实现思路**：
- 后端新增接口：按站点统计 `stop_times` 记录数，返回 `{stop_id, lat, lon, frequency}`
- 前端 Map.vue 叠加热力图层（引入 `leaflet.heat` 插件）
- 支持按时段（早高峰/晚高峰/全天）和线路类型筛选

**所需数据**：`stops` + `stop_times` 表（已有）

---

### 2. 线路运营时间分析

**功能描述**：展示每条线路的首末班时间、发车间隔分布、高峰/平峰班次密度对比。

**实现思路**：
- 后端从 `stop_times` 表提取每条线路的首末班时间和发车间隔
- 计算高峰时段（7-9, 17-19）与平峰时段的班次密度比
- 前端用时间轴图和柱状图展示

**所需数据**：`trips` + `stop_times` + `calendar` 表（已有）

---

### 3. 准点率报告自动生成

**功能描述**：按周/月自动汇总准点率数据，生成可下载的分析报告（PDF），包含趋势图、最佳/最差线路排名、异常时段分析。

**实现思路**：
- 后端新增 `/api/reports/punctuality` 接口，聚合 `route_daily_punctuality` 数据
- 使用 `reportlab` 或 `WeasyPrint` 生成 PDF 报告
- 前端在准点率概览页添加"生成报告"按钮

**所需数据**：`route_daily_punctuality` + `hourly_punctuality_stats` 表（已有）

---

### 4. 站点可达性分析

**功能描述**：选择一个站点，展示在指定时间内（如 30 分钟、60 分钟）可到达的所有站点范围，在地图上绘制等时圈。

**实现思路**：
- 复用换乘规划器的图搜索逻辑，从起点站 BFS 扩展
- 按到达时间分层（15min / 30min / 45min / 60min）
- 前端在地图上用不同颜色的多边形绘制等时圈

**所需数据**：`stops` + `stop_times` + `trips` 表（已有）

---

### 5. 线路重叠度分析

**功能描述**：分析两条或多条线路之间的站点重叠情况，识别平行线路和可替代线路。

**实现思路**：
- 后端计算任意两条线路的共同站点数 / 总站点数，得出重叠率
- 支持查看某条线路的所有"相似线路"排名
- 前端在线路详情页展示相似线路列表，在地图上叠加显示

**所需数据**：`routes` + `trips` + `stop_times` + `stops` 表（已有）

---

### 6. 历史数据回放

**功能描述**：在地图上按时间轴回放某天的车辆位置变化，动态展示全网运营状态。

**实现思路**：
- 后端新增接口：按日期和时间范围查询 `realtime_vehicle_positions` 历史记录
- 前端地图添加时间轴滑块，按时间戳动态渲染车辆标记点
- 支持播放/暂停/倍速控制

**所需数据**：`realtime_vehicle_positions` 表（已有，需确保历史数据未被清理）

---

### 7. 票价查询与比价

**功能描述**：根据起终点站查询票价，支持不同乘客类型（成人/学生/老人）的票价对比。

**实现思路**：
- 利用已有的 `fare_attributes`、`fare_rules`、`fare_rider_categories`、`rider_categories` 表
- 后端新增 `/api/fares/query` 接口，根据起终点匹配票价规则
- 前端在换乘规划结果中附加票价信息

**所需数据**：`fare_*` 和 `rider_categories` 表（已有）

---

### 8. 线路准点率异常检测与预警

**功能描述**：基于历史准点率数据，自动检测异常波动（如某线路准点率突然下降 20%），在管理看板高亮预警。

**实现思路**：
- 后端计算每条线路近 7 天准点率的均值和标准差
- 当日准点率偏离均值超过 2 个标准差时标记为异常
- 管理看板新增"异常预警"卡片，列出当日异常线路

**所需数据**：`route_daily_punctuality` 表（已有）

---

## 三、需要额外获取数据才能实现的功能

### 1. 真实客流量分析

**功能描述**：展示各线路、站点的实际乘客上下车数量，分析高峰时段客流分布和拥挤热点。

**需要获取的数据**：

| 地区 | 数据类型 | 获取地址 |
|------|---------|---------|
| 旧金山 | SFMTA 客流统计数据 | https://www.sfmta.com/reports/muni-ridership-data |
| 纽约 | MTA 地铁闸机数据（Turnstile Data） | http://web.mta.info/developers/turnstile.html |
| 悉尼 | TfNSW Opal 卡出行数据 | https://opendata.transport.nsw.gov.au/dataset/opal-trips |

**实现思路**：
- 下载客流数据，导入新增的 `ridership_records` 表
- 后端提供按线路/站点/时段的客流统计接口
- 前端用柱状图、热力图展示客流分布

---

### 2. 天气关联分析

**功能描述**：分析天气条件（降雨、高温、大风等）对准点率的影响，展示天气-准点率关联图表。

**需要获取的数据**：

| 地区 | 数据类型 | 获取地址 |
|------|---------|---------|
| 全球通用 | OpenWeatherMap 历史天气 API | https://openweathermap.org/history （免费层支持 5 天历史） |
| 全球通用 | Visual Crossing 天气历史数据 | https://www.visualcrossing.com/weather-data （免费 1000 次/天） |
| 澳大利亚 | BOM 气象数据 | http://www.bom.gov.au/climate/data/ |

**实现思路**：
- 每日获取三个城市的天气数据，存入 `weather_records` 表（date, region, temp, rain, wind, condition）
- 后端计算天气条件与准点率的相关系数
- 前端用散点图展示天气-准点率关系，用折线图叠加天气和准点率趋势

---

### 3. 周边 POI（兴趣点）信息

**功能描述**：在站点详情页展示周边设施（学校、医院、商场、景点等），帮助用户了解站点周边环境。

**需要获取的数据**：

| 数据源 | 说明 | 获取地址 |
|--------|------|---------|
| OpenStreetMap Overpass API | 免费，全球 POI 数据 | https://overpass-api.de/api/interpreter |
| Google Places API | 商业级 POI，每月 $200 免费额度 | https://developers.google.com/maps/documentation/places/web-service |
| Foursquare Places API | 免费层每月 10 万次调用 | https://developer.foursquare.com/ |

**实现思路**：
- 根据站点经纬度，调用 POI API 获取半径 500m 内的设施
- 缓存到 `stop_pois` 表，避免重复请求
- 前端站点详情页新增"周边设施"标签页，地图上标注 POI 图标

---

### 4. 交通事件与施工信息

**功能描述**：展示影响公交运营的交通事件（事故、施工、临时改道等），在地图上标注并关联受影响线路。

**需要获取的数据**：

| 地区 | 数据类型 | 获取地址 |
|------|---------|---------|
| 旧金山 | 511 SF Bay 交通事件 API | https://511.org/open-data/transit （需 API Key，同现有 Key） |
| 纽约 | MTA Service Alerts (GTFS-RT) | https://api.mta.info/#/subwayRealTimeFeeds （Alerts feed） |
| 悉尼 | TfNSW 交通预警 API | https://opendata.transport.nsw.gov.au/dataset/public-transport-realtime-alerts |

**实现思路**：
- 定时拉取各地区的 Service Alerts 数据（GTFS-RT Alerts 格式）
- 存入 `service_alerts` 表（alert_id, region, route_ids, description, start_time, end_time, cause, effect）
- 前端地图上用警告图标标注，线路详情页展示当前生效的预警信息

---

### 5. 无障碍设施信息

**功能描述**：展示各站点的无障碍设施情况（电梯、坡道、盲道、轮椅位等），方便特殊需求乘客出行规划。

**需要获取的数据**：

| 地区 | 数据类型 | 获取地址 |
|------|---------|---------|
| 旧金山 | GTFS Pathways 数据（部分站点已包含） | 已在 GTFS 数据中，检查 `pathways.txt` |
| 纽约 | MTA 无障碍站点列表 | https://new.mta.info/accessibility |
| 悉尼 | TfNSW 无障碍设施数据 | https://opendata.transport.nsw.gov.au/dataset/accessible-stops |

**实现思路**：
- 导入无障碍数据到 `stop_accessibility` 表
- 站点详情页新增无障碍信息标签
- 换乘规划器支持"仅无障碍路线"筛选选项

---

### 6. 人口与社区数据叠加

**功能描述**：将人口密度、收入水平、年龄分布等社区数据与公交覆盖范围叠加分析，评估公交服务公平性。

**需要获取的数据**：

| 地区 | 数据类型 | 获取地址 |
|------|---------|---------|
| 美国（SF/NYC） | Census Bureau ACS 数据 | https://data.census.gov/ |
| 美国（SF/NYC） | Census Bureau API | https://api.census.gov/data.html （免费，需申请 Key） |
| 悉尼 | ABS 人口普查数据 | https://www.abs.gov.au/census/find-census-data |

**实现思路**：
- 下载社区级别的人口统计数据，导入 `community_demographics` 表
- 计算各社区的公交覆盖率（站点密度、线路数、班次频率）
- 前端用分层地图展示公交服务与人口需求的匹配度

---

## 功能优先级建议

| 优先级 | 功能 | 类别 | 理由 |
|--------|------|------|------|
| ★★★ | 站点服务频率热力图 | 二 | 视觉效果好，实现简单，展示数据分析能力 |
| ★★★ | 线路运营时间分析 | 二 | 充分利用现有数据，实用性强 |
| ★★★ | 数据导出中心 | 一 | 通用辅助功能，提升系统实用性 |
| ★★☆ | 准点率报告自动生成 | 二 | 展示数据分析深度，适合毕设展示 |
| ★★☆ | 天气关联分析 | 三 | 跨领域数据融合，学术价值高 |
| ★★☆ | 交通事件与施工信息 | 三 | 利用 GTFS-RT Alerts，与现有实时数据体系一致 |
| ★★☆ | 站点可达性分析 | 二 | 算法展示价值高，复用换乘规划逻辑 |
| ★★☆ | 准点率异常检测与预警 | 二 | 展示数据挖掘能力 |
| ★☆☆ | 深色模式 | 一 | 锦上添花，非核心 |
| ★☆☆ | 多语言国际化 | 一 | 工作量大，收益有限 |
