# GTFS 公交数据分析系统 - 新增功能建议

> 基于现有数据和已实现功能，以下功能均可在当前技术栈（Flask + PostgreSQL + Vue3）上实现。

---

## 一、可直接实现（现有数据已足够）

### 1. 换乘规划器
**功能描述**：用户选择出发站和目的站，系统推荐最优换乘方案（最少换乘次数、最短时间）。

**实现思路**：
- 利用现有 `stop_times`、`trips`、`routes`、`stops` 表构建站点-线路图
- BFS/Dijkstra 算法计算最优路径
- 前端展示换乘步骤、预计时间、涉及线路

**所需数据**：已有，无需额外获取。

---

### 2. 线路对比分析
**功能描述**：同时选择 2-4 条线路，横向对比准点率、班次密度、覆盖站点数、高峰延误等指标。

**实现思路**：
- 复用现有 `route_daily_punctuality`、`hourly_punctuality_stats` 数据
- 前端用雷达图或并排柱状图展示对比结果

**所需数据**：已有。

---

### 3. 站点客流热力图
**功能描述**：在地图上以热力图形式展示各站点的班次密度（以班次数量代替客流量），识别高密度枢纽站。

**实现思路**：
- 统计每个站点经过的 `stop_times` 记录数作为热度值
- 地图组件（已有 Map.vue）叠加热力图层（Leaflet.heat 或 Mapbox）

**所需数据**：已有。

---

### 4. 时刻表导出
**功能描述**：在线路详情或站点详情页，支持将时刻表导出为 PDF 或 CSV 文件。

**实现思路**：
- 后端复用现有 `/api/trips/<trip_id>/stop_times` 接口数据
- 前端用 `jsPDF` 或直接生成 CSV Blob 下载

**所需数据**：已有。

---

### 5. 准点率报告自动生成
**功能描述**：按周/月自动汇总准点率数据，生成可下载的分析报告（PDF），包含趋势图、TOP/BOTTOM 线路、异常时段。

**实现思路**：
- 后端定时任务聚合 `route_daily_punctuality` 数据
- 使用 `reportlab` 或 `WeasyPrint` 生成 PDF
- 前端提供下载入口

**所需数据**：已有。

---

### 6. 个性化通知订阅
**功能描述**：用户可订阅关注的线路，当该线路准点率低于阈值时收到系统内通知（站内消息）。

**实现思路**：
- 新增 `user_subscriptions` 表（user_id, region, route_id, threshold）
- 后台定时检查准点率，写入 `user_notifications` 表
- 前端顶部导航栏显示未读通知数

**所需数据**：已有，需新增两张小表。

---

### 7. 历史数据回放
**功能描述**：在地图上按时间轴回放某天的车辆位置变化，直观展示运营全貌。

**实现思路**：
- 复用 `realtime_vehicle_positions` 历史记录（已有 `position_timestamp`）
- 前端地图加时间轴滑块，按时间戳过滤并动态渲染车辆位置

**所需数据**：已有（需确保历史位置数据未被定期清理）。

---

## 二、需要补充数据才能实现

### 8. 真实客流量分析
**功能描述**：展示各线路、站点的实际乘客上下车数量，分析高峰时段和拥挤热点。

**缺失数据**：乘客上下车计数（APC 数据）。

**如何获取**：
- **旧金山**：511 SF Bay API 提供部分 APC 数据，申请地址：https://511.org/open-data/token
- **纽约**：MTA 提供地铁进出站数据（turnstile data），下载地址：http://web.mta.info/developers/turnstile.html
- **悉尼**：TfNSW Opal 卡数据（需申请研究用途授权）

---

### 9. 票价查询与费用估算
**功能描述**：用户查询两站之间的票价，换乘规划时显示总费用。

**缺失数据**：完整的 `fare_rules` 和 `fare_attributes` GTFS 数据（当前 schema 有表但可能未导入）。

**如何获取**：
- 重新导入 GTFS ZIP 时确认 `fare_rules.txt` 和 `fare_attributes.txt` 文件存在并导入
- 旧金山：GTFS ZIP 中通常包含，用 `--clean` 重新导入即可
- 纽约/悉尼：从各自官方 GTFS 静态数据包中获取

**验证方式**：
```bash
psql gtfs_db -c "SELECT COUNT(*) FROM fare_attributes WHERE region='sf';"
```

---

### 10. 天气与延误相关性分析
**功能描述**：将历史延误数据与天气数据关联，分析雨天/大风对准点率的影响程度。

**缺失数据**：历史天气数据。

**如何获取**：
- **Open-Meteo**（免费，无需 API Key）：https://open-meteo.com/en/docs/historical-weather-api
  - 支持按经纬度和日期查询历史天气（温度、降水量、风速）
  - 示例：`https://archive-api.open-meteo.com/v1/archive?latitude=37.77&longitude=-122.42&start_date=2024-01-01&end_date=2024-12-31&daily=precipitation_sum,windspeed_10m_max`
- 将天气数据存入新表 `weather_records(region, date, precipitation_mm, wind_speed, weather_code)`，与 `route_daily_punctuality` 按日期 JOIN 分析

---

### 11. 无障碍设施查询
**功能描述**：标注各站点的无障碍设施情况（电梯、轮椅坡道），支持按无障碍条件筛选路线。

**缺失数据**：`stops.wheelchair_boarding` 和 `trips.wheelchair_accessible` 字段（GTFS 标准字段，可能未导入）。

**如何获取**：
- 检查现有 GTFS ZIP 中 `stops.txt` 是否包含 `wheelchair_boarding` 列
- 若有，在 `schema.sql` 中为 `stops` 表添加该字段并重新导入
- 旧金山 Muni 的 GTFS 数据通常包含此字段

**验证方式**：
```bash
python3 -c "import zipfile; z=zipfile.ZipFile('gtfs_data/gtfs_SF_20251119.zip'); import csv; r=csv.DictReader(z.open('stops.txt').read().decode().splitlines()); print(r.fieldnames)"
```

---

### 12. 多城市跨地区对比看板
**功能描述**：在同一页面对比旧金山、纽约、悉尼三个城市的系统级指标（准点率、线路数、覆盖站点、日均班次）。

**缺失数据**：NYC 和 Sydney 的准点率历史数据（需运行对应地区的准点率收集服务）。

**如何获取**：
```bash
# 启动纽约准点率收集（需 MTA API Key）
MTA_API_KEY=your_key python3 backend/scripts/start_punctuality_service.py --region nyc &

# 悉尼已有 API Key，直接启动
python3 backend/scripts/start_punctuality_service.py --region sydney &
```
收集 1-2 天数据后即可展示对比。

| 高 | 时刻表导出 | 低 | ✅ |
| 中 | 站点客流热力图 | 低 | ✅ |
| 中 | 个性化通知订阅 | 中 | ✅ |
| 中 | 多城市跨地区对比 | 低 | 需收集数据 |
| 中 | 票价查询 | 低 | 需验证导入 |
| 低 | 准点率报告导出 | 中 | ✅ |
| 低 | 历史数据回放 | 中 | ✅ |
| 低 | 天气与延误相关性 | 高 | 需获取天气数据 |
| 低 | 无障碍设施查询 | 低 | 需验证字段 |
| 低 | 真实客流量分析 | 高 | 需申请数据 |
